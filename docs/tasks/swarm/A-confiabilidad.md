Tarea A (confiabilidad): que el estado de una tarea dependa de evidencia que Silka comprueba, nunca de lo que diga el agente.

Contexto: `src/silka/tasks/` (manager, verify, card, supervisor, plan, model, risk), `src/silka/review/`, `src/silka/codemode/` (silka.d.ts, api-schema, api-dispatch), specs `docs/specs/features/F2-tareas-aisladas.md` y `F3-bandeja-revision.md` (SEC-07, SEC-08, SEC-09).

1. Ficha con evidencia. La ficha tiene `evidence` (verify y criterios: comando, código de salida, duración, ref al log) calculada por Silka. El texto del agente va aparte en `agentSays`, escapado (SEC-09) y marcado como dicho por el agente; nunca cambia el estado. Prueba: un agente falso termina diciendo "tests OK, todo listo" pero verify falla → la tarea NO queda "lista para revisión".
2. Verify obligatorio, inferido. Si la tarea no declara `verify`, Silka lo infiere del worktree: `package.json` (scripts test, lint, typecheck, en ese orden, los que existan, con el gestor según el lockfile), `pyproject.toml`/`pytest.ini` → `python -m pytest`, `Cargo.toml` → `cargo test`, `go.mod` → `go test ./...`. La ficha marca `verifySource: "inferido"`. Si no se puede inferir: `E_TASK_INVALID` al lanzar, salvo `allowNoVerify: true`, que fuerza riesgo alto (solo humano).
3. Criterios de aceptación. La tarea admite `accept: [...]` con tres tipos: `{ cmd: "..." }`, `{ grep: { pattern, path, absent?: true } }` y `{ file: { path, exists: true|false } }`. Silka los comprueba en el worktree después de verify (grep y file sin shell, en JS; path confinado al worktree). El resultado de cada criterio va en `evidence`. Solo se ejecutan los comandos declarados (SEC-07).
4. Reparación automática acotada. Si verify o algún criterio falla, el supervisor envía a la MISMA sesión el error íntegro (comando, salida recortada solo en tamaño con ref al log completo, criterio que falló) y la tarea vuelve a "trabajando". Máximo `maxRepairs` (por defecto 2, configurable por tarea). El contador se persiste: es idempotente si el hub se reinicia. Agotados los intentos → "verificación fallida" en la bandeja.
